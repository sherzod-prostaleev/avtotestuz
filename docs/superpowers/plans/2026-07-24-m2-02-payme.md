# M2-02 Payme Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline) or subagent-driven-development. Steps use `- [ ]`.

**Goal:** Payme Merchant API (JSON-RPC) webhook + checkout-initiate so a user pays via Payme and gets a VIP entitlement, in sandbox mode.

**Architecture:** `payment` = our order; `payme_transaction` = Payme's transaction (state/ms-times). Public `POST /billing/payme` Basic-auth webhook dispatches the 6 methods; authed `POST /me/checkout` creates a payment + returns the base64 Payme checkout URL. PerformTransaction grants VIP via `billing.Service.GrantDays`.

**Tech Stack:** Go, chi, pgx, sqlc. Amounts: DB so'm, Payme tiyin (×100). Tests: `testdb`, `-p 1`.

## Global Constraints
- `PATH="$HOME/.local/go/bin:$PATH"` for go; sqlc at `~/go/bin`; `make generate` for sqlc.
- Webhook ALWAYS returns HTTP 200; errors are JSON-RPC error objects.
- Basic-auth login literal `Paycom`; password = `PAYME_TEST_KEY`/`PAYME_KEY` per `PAYME_ENV`. Empty key ⇒ reject `-32504`.
- Error codes: -32300 (not POST), -32700 (parse), -32601 (method), -32504 (auth), -31001 (amount), -31003 (txn not found), -31008 (state), -31050 (account, `data`="order_id"). Account errors need `message{ru,uz,en}`+`data`.
- State: 1 pending, 2 paid, -1 cancelled-pending, -2 cancelled-performed. Times = Unix ms. 12h (43_200_000ms) pending ⇒ expired.
