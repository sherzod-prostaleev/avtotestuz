# M2-05 Promo Codes Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Implement backend support for promo codes (validation API `POST /billing/promo/validate`, discount application during checkout, zero-amount checkout flow, and redemption tracking upon payment completion).

**Architecture:** Add sqlc queries for `promo_code` lookup and `promo_redemption` counting/creation; implement promo validation & discount calculations in `internal/billing`; integrate promo processing into `/me/checkout` and `GrantDays`.

**Tech Stack:** Go, chi, pgx, sqlc. Tests: `testdb`, `-p 1`.

## Global Constraints
- `export PATH="$HOME/.local/go/bin:$HOME/go/bin:$PATH"` for go/sqlc; `make generate` for sqlc (repo root).
- Always use `LOWER(code)` for case-insensitive promo code lookup.
- Respect `active`, `valid_from`, `valid_to`, `max_uses`, and `per_user_limit`.
- Zero-amount (100% discount) checkout completes immediately without external provider redirect.
- `promo_redemption` record is created only when payment status transitions to `paid`.

### Task 1: Promo DB queries & `ValidatePromo` service logic
**Files:**
- Modify `backend/internal/db/queries/billing.sql`
- Modify `backend/internal/billing/service.go`
- Create `backend/internal/billing/promo.go`
- Create `backend/internal/billing/promo_test.go`

- [ ] Add sqlc queries to `backend/internal/db/queries/billing.sql`:
  ```sql
  -- name: GetPromoCodeByCode :one
  SELECT id, code, kind, value, max_uses, per_user_limit, valid_from, valid_to, active, created_by
  FROM promo_code
  WHERE LOWER(code) = LOWER($1) AND active = true;

  -- name: CountPromoRedemptions :one
  SELECT COUNT(*)::int FROM promo_redemption WHERE promo_code_id = $1;

  -- name: CountUserPromoRedemptions :one
  SELECT COUNT(*)::int FROM promo_redemption WHERE promo_code_id = $1 AND profile_id = $2;

  -- name: CreatePromoRedemption :exec
  INSERT INTO promo_redemption (promo_code_id, profile_id, payment_id)
  VALUES ($1, $2, $3);

  -- name: UpdatePaymentPromoCode :exec
  UPDATE payment SET promo_code_id = $2 WHERE id = $1;
  ```
  Run `make generate` in backend root.

- [ ] Create `backend/internal/billing/promo.go`:
  - Define `ValidatePromoResult` struct.
  - Implement `ValidatePromo(ctx context.Context, profileID uuid.UUID, code string, tariffCode string) (ValidatePromoResult, error)` logic:
    - Load promo by code.
    - Check dates (`valid_from`, `valid_to`).
    - Check `max_uses` against `CountPromoRedemptions`.
    - Check `per_user_limit` against `CountUserPromoRedemptions`.
    - Load tariff by `tariffCode`.
    - Calculate discount amount (`percent`, `fixed`, `days`).
    - Return structured result.

- [ ] **TDD:** Write unit tests in `backend/internal/billing/promo_test.go` verifying discount calculation and limit validation.

### Task 3: Checkout with Promo & Zero-Amount Free Checkout
**Files:**
- Modify `backend/internal/billing/checkout.go`
- Modify `backend/internal/billing/service.go`
- Modify `backend/internal/billing/handlers_test.go`

- [ ] Update `StartCheckout` in `backend/internal/billing/checkout.go`:
  - Accept `promoCode string` parameter.
  - If `promoCode` is non-empty, call `ValidatePromo`.
  - Pass `promo_code_id` and calculated `finalAmount` to `CreatePayment`.
  - If `finalAmount == 0`:
    - Mark payment `paid` (`MarkPaymentPaid`).
    - Call `GrantDays` with promo bonus days if applicable.
    - Create `promo_redemption` record.
    - Return `CheckoutResult{PaymentID: id, CheckoutURL: ""}`.

- [ ] Update `GrantDays` in `backend/internal/billing/service.go`:
  - When payment has `promo_code_id`, insert into `promo_redemption`.
  - If promo is `kind == 'days'`, add bonus days to granted entitlement.

- [ ] Write integration test cases in `handlers_test.go` covering:
  - Checkout with percent/fixed promo code.
  - 100% discount zero-amount checkout.
  - Verification that `promo_redemption` is recorded upon successful payment.
